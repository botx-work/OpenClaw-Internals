## 核心组件
- 安装与初始化
  - 推荐使用安装脚本一键完成 Node 检测/安装与首次引导；或通过包管理器安装后运行设置向导。
  - Windows 用户可使用 PowerShell 脚本，自动处理执行策略与依赖。
- 设置向导（CLI）
  - 交互式引导你完成模型/认证、工作空间、网关、渠道、守护进程与健康检查、技能安装等步骤。
- 工作空间与模板
  - 默认工作空间位于用户目录下，内置 AGENTS.md、SOUL.md、TOOLS.md 等模板，支持复制与替换。
- macOS 首次引导（应用）
  - 引导选择网关运行位置、权限授予、本地/远程模式、CLI 安装等，确保首次体验顺畅。

## 详细组件分析

### 组件一：安装与初始化（跨平台）
- macOS/Linux
  - 使用官方安装脚本，自动检测/安装 Node 并全局安装 openclaw，随后可直接运行设置向导。
  - 支持跳过首次引导仅安装二进制。
- Windows
  - PowerShell 脚本自动处理执行策略、Node/Git 检测与安装，最终输出 openclaw 可用提示。
- 包管理器安装
  - npm/pnpm 安装后，同样可直接运行设置向导；如遇到构建依赖问题，脚本会尝试自动安装必要工具。

## 性能与安全建议
- 性能
  - 使用 Node 24（推荐）以获得最新性能与稳定性；若使用较老版本，仍可兼容。
  - 在 Linux/WSL2 上运行可显著提升通道与工具链的响应速度。
- 安全
  - 默认情况下，工具在主会话中运行；在群组/频道场景中建议启用沙箱策略，限制工具集。
  - 对于处理 webhook/钩子内容的场景，优先选用更强的模型，并严格限制工具策略与沙箱。
- 网络暴露
  - 如需远程访问，可通过 TailScale Serve/Funnel 暴露网关，但需正确配置鉴权与密码策略。

## 故障排查指南
- openclaw 命令找不到
  - 检查全局 npm bin 是否在 PATH 中；在 macOS/Linux 下通常为 $(npm prefix -g)/bin；Windows 为 $(npm prefix -g)。
  - 新建终端或刷新缓存后再试。
- 安装失败（npm）
  - 若出现构建工具缺失错误，脚本会尝试自动安装；也可手动安装编译工具链（make、cmake、gcc 等）。
- Windows 执行策略限制
  - PowerShell 执行策略可能阻止脚本运行；可在当前进程临时放宽或以管理员身份设置策略。
- 网关无法启动或端口占用
  - 检查端口占用情况，或调整网关监听端口；确认防火墙放行。
- 渠道连接失败
  - 确认渠道所需的令牌/密钥已正确配置；对 Telegram/WhatsApp 等渠道，注意允许列表与分组策略。
