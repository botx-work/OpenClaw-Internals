## 简介
OpenClaw 是一个“本地优先”的个人 AI 助手平台，强调在用户自己的设备上运行，连接用户已有的即时通讯渠道，并提供强大的工具与自动化能力。其核心价值主张包括：
- 本地优先：所有数据与计算尽可能在本地完成，降低隐私与安全风险。
- 多渠道即时通讯集成：支持 WhatsApp、Telegram、Discord、Slack、Google Chat、Signal、iMessage（通过 BlueBubbles）、IRC、Microsoft Teams、Matrix、Feishu、LINE、Mattermost、Nextcloud Talk、Nostr、Synology Chat、Tlon、Twitch、Zalo、Zalo Personal、WebChat 等。
- 强大的控制平面：以单一 WebSocket 网关作为控制面，统一管理会话、通道、工具与事件。
- 可扩展的运行时：基于 Pi Agent 的 RPC 模式，支持工具流式输出与块级流式输出。
- 完整的生态：配套的 macOS/iOS/Android 节点、浏览器控制、Canvas/A2UI 视觉工作区、语音唤醒与通话、技能与插件生态。

OpenClaw 的设计理念是“可运行的真实任务”，既尊重隐私与安全，又保持强大与易用性。项目当前聚焦于安全与稳定、首次运行体验、以及对主流模型提供商与消息渠道的支持。

## 项目结构
仓库采用多模块组织方式，涵盖核心运行时、CLI、网关、通道插件、应用与节点、文档与脚本等。关键目录与职责概览：
- 根目录：包定义、入口脚本、构建与测试脚本、文档索引与国际化资源。

- extensions：各即时通讯渠道的插件实现，按平台拆分。
- apps：macOS/iOS/Android 应用与共享库，提供节点能力与本地交互。

- docs：完整的概念、操作与参考文档，覆盖架构、通道、网关、工具、平台等。
- scripts：构建、测试、发布、协议生成、UI 打包等自动化脚本。
- assets：浏览器扩展等辅助资源。

## 核心组件
- 网关（Gateway）：单一路由与控制平面，负责维护各消息提供商连接、暴露 WebSocket 控制面 API、事件推送、HTTP 工具与兼容接口、以及服务生命周期管理。
- Pi Agent 运行时：嵌入式代理运行时（基于 pi-mono），提供会话管理、工具调用、上下文注入与流式输出能力。
- 通道插件（Channels）：针对不同即时通讯平台的适配器，统一接入网关控制面。
- 节点（Nodes）：macOS/iOS/Android 设备节点，提供本地能力（如摄像头、屏幕录制、位置、通知、系统命令执行等）并通过网关进行授权调用。
- 工具与自动化：浏览器控制、Canvas/A2UI、节点工具、定时任务、Webhook、Gmail Pub/Sub 等。
- 控制 UI 与 WebChat：通过网关端口提供可视化控制与聊天界面。
- 安全与权限：默认安全策略、沙箱模式、设备配对与签名、远程访问（Tailscale/SSH 隧道）与认证。

## 架构总览
OpenClaw 的整体架构围绕“单一网关控制平面 + 多客户端/节点”展开。网关负责：
- 维护与各消息提供商的连接；
- 提供类型化 WebSocket API（请求/响应/事件）；
- 管理会话、路由、工具与事件；
- 对外暴露 HTTP 接口（OpenAI 兼容、工具调用、控制 UI）。

## 详细组件分析

### 网关（Gateway）
- 单一进程常驻，统一承载路由、控制平面与通道连接。
- 默认绑定回环地址，需认证后方可使用；支持热重载与多种重启策略。
- 提供 WebSocket 控制面与 HTTP 服务，统一处理健康检查、状态查询、消息发送、代理调用、工具执行等。
- 支持多网关实例隔离部署，确保严格隔离与冗余场景。

### Pi Agent 运行时
- 基于 pi-mono 的嵌入式代理运行时，提供会话管理、上下文注入、工具调用与流式输出。
- 工作区（Workspace）为代理唯一工作目录，注入 AGENTS.md、SOUL.md、TOOLS.md 等引导文件。
- 支持队列模式（steer/followup/collect）与块级流式输出策略，便于在多消息并发场景下保持一致性与低延迟。

```mermaid
flowchart TD

LoadWorkspace --> InjectContext["注入上下文(AGENTS/SOUL/TOOLS/USER...)"]
InjectContext --> ToolPolicy["应用工具策略与沙箱规则"]
ToolPolicy --> RunLoop{"是否仍有待处理消息?"}
RunLoop --> |是| InjectMsg["注入新消息到当前运行"]
InjectMsg --> RunLoop
RunLoop --> |否| StreamBlocks["块级流式输出/合并片段"]
StreamBlocks --> End(["结束回合"])
```

### 通道（Channels）
- 支持广泛的消息平台，每个通道通过网关统一接入，文本通用，媒体与互动能力因平台而异。
- 配对与白名单策略保障私域 DM 安全，默认仅允许已配对或白名单内的发件人。
- 支持群组路由、提及门控、回复标签与分片路由，满足复杂协作场景。

### 安全与权限
- 默认安全策略：工具在主会话中默认运行，群组/频道会话可通过沙箱模式隔离；提供工具白名单/黑名单与权限映射。
- 设备配对与签名：所有客户端连接需携带设备身份并签名挑战，非本地连接仍需显式批准。
- 远程访问：推荐 Tailscale/VPN，或 SSH 隧道；远端访问仍需网关认证。

## 性能考量
- 会话压缩与令牌使用跟踪：通过会话修剪与使用统计优化成本与延迟。
- 流式与块级输出：支持块级流式输出与合并，减少细粒度消息带来的网络与渲染压力。
- 沙箱与隔离：在群组/频道会话中启用沙箱，避免高风险工具对主机造成影响。
- 并发与队列：队列模式（steer/followup/collect）与注入策略保证在并发输入下的稳定性与一致性。

## 故障排查指南
- 网关启动与健康：使用 `openclaw gateway status`、`openclaw health`、`openclaw logs --follow` 检查运行状态与日志。
- 端口与认证：若出现“拒绝绑定且未认证”或“端口占用”，请检查绑定模式与认证配置，或使用 `--force` 强制重启监听。
- 连接失败：确认首次帧必须为 `connect`，并携带正确的认证令牌；非本地连接仍需显式批准。
- 渠道探测：使用 `openclaw channels status --probe` 检查各通道连通性。
- 远程访问：通过 Tailscale/VPN 或 SSH 隧道连接，但需保持网关认证一致。

## 结论
OpenClaw 将“本地优先、隐私安全、多渠道集成、强工具链”有机结合，形成一套可扩展、可运营、可进化的个人 AI 助手平台。其以单一网关为控制面，配合 Pi Agent 运行时与丰富的通道/节点/工具生态，既能满足日常助理需求，也能支撑复杂自动化与协作场景。随着对主流模型提供商与消息渠道的支持持续完善，以及性能与可用性的稳步提升，OpenClaw 将成为个人与小团队的首选本地 AI 助手解决方案。
